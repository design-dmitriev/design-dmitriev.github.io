## Как устроен сайт

Главная — статическая страница без сборки: `index.html` + CSS/JS/JSON. В репозитории также остались файлы прежнего экспорта Next.js, но пересобирать его для главной не нужно. `/new-site/` — старый адрес, перенаправляющий на главную; `/preview/` не является основной версией.

| Файл / каталог | Назначение |
| --- | --- |

| `assets/graphic.css` | Первый экран, возвращённый flow-градиент, оформление работ |

## Текущее оформление

- Inter используется в главном интерфейсе, на страницах проектов и в просмотре работ. Файлы Zarya сохранены для дальнейшей разработки.
- Первый экран — исходный плавный чёрно-белый flow-градиент, без коллажа.
- Фиксированная шапка: имя слева, четыре раздела по центру, CV справа. Плашки полупрозрачные с размытием и внешней тенью, без белой кромки и внутреннего блика.
- На телефоне: фамилия, CV, меню. Внизу сохраняется навигация по четырём разделам.
- Меню «Обо мне» содержит результаты, процессы, команду, опыт и условия; закрывается после выбора, снаружи и по Escape.
- В проектах видны Folderify и сборщик коробочек. Web-App скрыт атрибутом `hidden` в главной; Zarya в актуальном списке отсутствует. Сами страницы не удалены.
- «Опыт работы» — компания, роль и даты слева, обязанности справа; на телефоне одна колонка. Четыре позиции и 27 пунктов сохранены.

## Локальный просмотр и адаптив

```sh
cd /Users/starlight.lnk/Developer/design-dmitriev.github.io
python3 -m http.server 8766
```

Открыть `http://localhost:8766/`, а не `file://`: динамическим JSON и вложенным просмотрам нужен HTTP.

Рабочая копия использует **sparse checkout** и частичную загрузку объектов. Некоторые тяжёлые изображения и страницы могут отсутствовать локально, хотя присутствуют в GitHub. Не принимать их локальное отсутствие за удаление на сайте. Проверить включённые пути:

```sh
git sparse-checkout list
```

Добавлять только нужные пути, например `git sparse-checkout add '/portfolio/img/zaryadka-iphone/'`. Полная выгрузка всех медиа может быть большой; не отключать sparse checkout без необходимости. Прокси-просмотр из временной папки, использованный в прежнем чате, не является частью проекта и не нужен для публикации.

Любая веб-правка включает мобильную версию: 320–360 px, 390–430 px, планшет 768 px, компьютер и альбомный экран. Проверять скриншоты, переполнение, меню, окна кейсов и размеры кнопок. Физический телефон и браузерная эмуляция — разные виды проверки.

## Проверка и публикация

Для статической правки сборка не требуется. Базовые проверки:

```sh
git diff --check
node --check assets/mobile.js
node --check assets/detail.js
```

Затем проверить затронутый интерфейс в браузере. Коммитить только относящиеся к задаче файлы, например:

```sh
git -c user.name=Starlight_lnk -c user.email=alex.strl1t@gmail.com commit -m "Describe the actual change"
git push origin main
/Users/starlight.lnk/.local/bin/gh run list --repo design-dmitriev/design-dmitriev.github.io --limit 3 --json databaseId,status,conclusion,headSha
```

Для нужного запуска проверить `gh run view RUN_ID --repo design-dmitriev/design-dmitriev.github.io --json status,conclusion`. Дождаться `completed` + `success` у `pages build and deployment`. На сайте можно добавить `?v=SHORT_COMMIT` для обновления страницы; отдельно должны быть обновлены версии изменённых ресурсов.
